# 추천 · 수면 패턴 · AI 로드맵 (제안)

> 아직 만들지 않은 기능의 설계 메모입니다. **데이터를 먼저 모으고 → 통계로 추천 → AI** 순서로 가는 걸 권합니다.
> AI는 데이터가 없으면 똑똑해질 수 없고, 반대로 단순 통계만으로도 초기 추천은 충분히 좋아집니다.

---

## 1단계: 취향과 수면 신호 모으기 (AI 없음, 베타 전에 넣기 좋음)

| 기능 | 내용 | 필요한 것 |
|------|------|------|
| **취향 온보딩** | 첫 실행 때 "어떤 소리에 잠이 와요?" → 소분류 3개 고르기 + 10초 미리듣기 👍/👎 | `user_preference(user_id, category_id, score)` |
| **재생 기록 강화** | 지금 `play_log`는 "재생 시작"만 기록. 들은 시간, 수면 타이머 값, 시작 시각대, 중간에 끈 위치를 추가 | `play_session(user_id, playlist_id, started_at, listened_seconds, sleep_timer_min, ended_by)` (V3) |
| **홈 "당신을 위한 소리"** | 선호 소분류 × 요즘 뜨는 소리 | SQL 한 줄 (지금 구조로 바로 가능) |

> "끝까지 들었는데 중간에 조작이 없었다" = 잠들었을 가능성이 높다는 좋은 신호입니다.

## 2단계: 통계 기반 추천 (AI 모델 없이도 꽤 정확)

- **함께 쓰는 소리**: 같은 플레이리스트에 같이 들어간 블록 쌍을 세면 "빗소리를 넣은 사람들은 브라운 노이즈도 넣었어요" 추천이 됩니다. 편집기 블록 상자 맨 앞에 추천 칩으로 보여주기
- **시간대별**: 밤 11시~새벽엔 노이즈·자연, 낮엔 카페·키보드처럼 시간대마다 인기 소분류가 다름
- **잘 자게 해준 조합 순위**: 1단계 수면 신호로 "끝까지 들은 비율"이 높은 공개 조합

## 3단계: 수면 패턴

- **아침 한 번 탭**: "어젯밤 잘 잤나요? 😴 😐 😫" 알림 → 조합별 수면 점수. 가장 부담 없고 가장 중요한 데이터
- **건강 앱 연동(선택)**: Apple 건강(HealthKit) / Android 헬스 커넥트의 수면 기록 읽기 → 잠든 시각·깬 횟수와 들은 조합을 연결. 개발 빌드(EAS)가 필요하고 권한 동의 화면이 들어갑니다
- **패턴 리포트**: "평일엔 브라운 노이즈 + 빗소리 조합에서 20분 빨리 잠들었어요" → 구독 기능 후보
- ⚠️ 수면 데이터는 민감한 개인정보에 가깝습니다: 꼭 필요한 것만 모으고, 개인정보 처리방침·동의·"내 데이터 삭제"를 함께 만들기 (회원 탈퇴 시 삭제는 이미 있음)
- 휴대폰 마이크로 코골이/뒤척임 감지는 배터리·개인정보 부담이 커서 나중으로

## 4단계: AI

| 아이디어 | 설명 | 추천도 |
|------|------|------|
| **말로 조합 만들기** | "비 오는 일본 골목에서 잠들고 싶어, 6시간" → LLM(예: Claude API의 tool use)이 **기존 블록 목록**(카테고리·태그·길이)에서 골라 `PlaylistSaveRequest` JSON을 만들고, 서버가 지금의 검증(10시간, 믹스 겹침)을 그대로 거쳐 저장 | ⭐⭐⭐ 바로 체감되는 "AI 기능". 새 음원을 만드는 게 아니라 저작권·품질이 안전하고, 무료 하루 N회 / 구독 무제한으로 수익화와 잘 맞음 |
| **업로드 자동 태깅** | 업로드한 음원을 분석해(ffmpeg로 음량 변화·주파수 대역) "부드러운/리드미컬한" 같은 태그와 소분류를 제안 → 관리자 승인이 빨라짐 | ⭐⭐ 크리에이터 마켓을 열 때 |
| **개인 맞춤 추천 모델** | 1~3단계 데이터가 쌓이면 사용자-블록 임베딩으로 추천 | ⭐⭐ 사용자가 수천 명 이상일 때 |
| AI로 ASMR 음원 자체 생성 | | ⭐ 초기엔 비추천: 품질이 들쭉날쭉하고 저작권·표기 정책이 아직 불확실 |

## 권장 순서

1. 취향 온보딩 + `play_session` (V3) — 베타 출시 전
2. 아침 수면 체크 + "함께 쓰는 소리" — 베타 중
3. 말로 조합 만들기(AI) — 구독 출시와 함께
4. 건강 앱 연동, 패턴 리포트 — 구독 사용자 늘어난 뒤
